# Deployment

The live site is https://tour-masters-apartments.onrender.com, hosted on Render's free plan and deployed from the `main` branch of this repository.

## How it is set up

- **Blueprint.** `render.yaml` defines one Node web service named `tour-masters-apartments`:
  - build: `npm ci`
  - start: `npm run seed && npm start` (loads the demo data, then starts the server)
  - health check: `/`
  - `NODE_VERSION` 24.11.1, and a generated `SESSION_SECRET`
- **Auto-deploy.** Render's GitHub app has access to this repository, and the service's Auto-Deploy is set to *On Commit*. A push to `main` builds and goes live in about a minute. A push from a fork or another branch does not deploy.
- **Manual deploy.** In the Render dashboard, open the service and use *Manual Deploy*.

## Settings

Set these under the service's **Environment** tab in Render. Locally they go in `.env` (copy `.env.example`).

| Variable | Needed for | Notes |
| --- | --- | --- |
| `SESSION_SECRET` | Logins that survive restarts | Generated by Render |
| `PUBLIC_URL` | Links in emails and Flutterwave's return link | Falls back to Render's `RENDER_EXTERNAL_URL` |
| `FLW_SECRET_KEY` | Real Mobile Money payments | Empty means the built-in simulator |
| `FLW_SECRET_HASH` | Flutterwave webhooks | Same value in Flutterwave's webhook settings, with the URL `https://<site>/webhooks/flutterwave` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Sending email alerts | Empty means emails are saved to `data/outbox/` |
| `DB_PATH`, `UPLOAD_DIR` | Keeping data on a persistent disk | Point both at the disk's mount path |
| `HERO_IMAGE_URL` | Landing-page fallback photo | Only used when no apartment has photos |

## Free plan limits

- **No persistent disk.** The database and uploaded photos are wiped on every deploy or restart, and the start command reloads the demo data. Anything visitors add is lost.
- **Sleeping.** The service sleeps after a while without visits; the next visit takes about 50 seconds while it wakes.

## Moving to real use

1. Upgrade the service to a paid plan and attach a persistent disk (for example mounted at `/var/data`).
2. Set `DB_PATH=/var/data/tour_masters.db` and `UPLOAD_DIR=/var/data/uploads`.
3. Change the start command in `render.yaml` to `npm start`, so the demo data is no longer loaded on each start. Run `npm run seed` once from the Render shell only if you want the demo data.
4. Set `PUBLIC_URL`, the Flutterwave live key and webhook hash, and the SMTP settings.
5. Set `cookie.secure` in `src/server.js` and use a persistent session store.

## Running locally

Requires Node.js 22.5 or newer.

```bash
npm install
npm run seed
npm start
```

The site is then at http://localhost:3000.
